Design principles

  • The model proposes, code decides. The triage model gives a verdict; the disposition comes from a confidence gate and deterministic guardrails in code. The IR model extracts facts; the severity comes from a rubric in code.
  • Guardrails only add caution. A disabled account forces escalation; an unlisted admin account, a Tier-0 asset or instruction-like text in the alert blocks auto-close. None of them can make an outcome less cautious.
  • Reasoning and action are separate planes. Agents never call actuators. Internal, reversible actions run automatically; paging a person or contacting anyone outside security waits for human approval (OWASP LLM06 — Excessive Agency).
  • Alert text is untrusted data. Command lines and context fields are attacker-influenced, so they are scanned for prompt injection (LLM01) and always HTML-escaped in this console (LLM05).
  • Everything is audited. Each close, escalation, incident and action is logged with its rationale.
  • Engine plus org packs. Alert-source mappings, playbooks, roster, asset rules, severity cut-offs, escalation policy and outbound systems are files in orgs/<id>/. Alerting systems post vendor JSON to /api/ingest/{source}. An org can make the system more cautious, never less safe. See the Organization page.
